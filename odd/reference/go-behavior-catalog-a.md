## CONV: `convenio` (descargar, preparar, importar)

Purpose: get the Medicar convenio CSV, validate and enrich it per invoice against the nota técnica, and store the dataset in MySQL.

- Dependencies: `descargar` needs only Medicar and config. `preparar` needs the CSV from `descargar` (or a manual CSV), the `Nota tecnica.xlsx` workbook, MIPRES for EVENTO NO PBS, and MySQL when live. `importar` needs old folders with `Convenio_*.csv` and/or `convenio.json`. Everything downstream reads the dataset `preparar` writes.
- There is no `convenio mipres` subcommand. The MIPRES check is part of `preparar` (see CONV-17 to CONV-19).

Rows with the wrong field count are skipped and their line numbers logged as a warning. Values are trimmed, `123,00` becomes `123`, and scientific notation becomes plain digits. [src: internal/convenio/csv.go:60-190] [ext: none]
- CONV-11 — Prepared-format (manual) files: the optional columns `CLASIFICACION` (714/799), `MED-FORMA FARMACEUTICA RIPS`, `MED-CONCENTRACION MEDICAMENTO RIPS` and `MED-UNIDAD MEDIDA RIPS` are read when present. Drug fields then come from the file, with the nota técnica only back-filling blanks. `derechos validar` takes affiliate rights from the file instead of the validator. [src: docs/convenio.md:522-538; internal/convenio/prepare.go:337-339] [ext: none] [note: depends on the CSV carrying specific extra columns]

[src: cmd_convenio.go:177-198,405-422; internal/convenio/amount.go:19-30] [ext: MySQL] [note: the stored parameters override the config value unless the flag is explicit]
- CONV-13 — Nota técnica file resolution: `--nota-tecnica`, else `paths.automatic/Nota tecnica.xlsx`, else `Nota tecnica.xlsx` next to the CSV, else an error naming the name. Parsed by a stdlib XLSX reader using cached cell values (formulas without a cached value read as `=…`). The sheet is `EVENTO 2025`, else the first sheet with a recognized header in its first 31 rows. Two layouts exist, new and old. Catalog key is `normCode(COD GEN)|normCode(CUM)`, last duplicate wins. Type 714/799 passes through, and an empty value defaults to 714 if the CUM has `-` or is over 14 characters, else 799. [src: internal/convenio/prepare.go:37-63; docs/convenio.md:423-428] [ext: none] [note: the subplan strings are hardcoded defaults]
- CONV-15 — Per-invoice rules, first failure wins. Order: multiple affiliates (different tipo+documento pairs → REVISION_MANUAL `MULTIPLES_AFILIADOS_EN_FACTURA`, document numbers never printed), subplan filter, unparseable total, total above cap (`MONTO_MAXIMO_SUPERADO`), line not in catalog (`No cruza nota tecnica: …`), unit price above the agreed price when it is above 0 (`PRECIO_MAYOR_NOTA_TECNICA`), matched line without 714/799 (`SIN_CLASIFICACION_NOTA_TECNICA`). - CONV-16 — `--invoices` limits the run to the named invoices; unknown ids are warned about, and the command fails only if none match. `--limit N` counts only invoices that end prepared: excluded and manual-review ones are replaced by the next pending invoice, and the walk stops at N. Invoices not reached count as Ignored. Already-finished invoices (filed or closed with a note, from a read-only lookup of `radicacion_estado`) never consume the limit and are still processed. If that lookup fails, it only warns. The summary adds `limit: P/N prepared (…)`. [src: cmd_convenio.go:476-502; docs/convenio.md:497-520] [ext: MySQL] [note: the lookup runs whenever the DSN is set, including in dry-run]
- CONV-17 — MIPRES check, EVENTO NO PBS only, run last for invoices that passed every other rule. It also runs in dry-run, because the calls are read-only GETs. Per line with both `mipres` and `no. formula`: `GET {base}/api/EntregaXPrescripcion/{NIT}/{secondaryToken}/{prescription}`, once per distinct prescription per run. Deliveries are matched by `ID` (digits compare numerically, so `007` equals `7`). `EstEntrega` is 0 annulled, 1 not delivered, 2 delivered. Any 2 passes the line; otherwise annulled gives `MIPRES ANULADO`, then not delivered gives `MIPRES NO ENTREGADO`. ## PROC: `proceso run`

Purpose: stream every prepared invoice of one load folder through the per-invoice phases as worker pools, then batch radicación.

- Dependencies: runs `convenio preparar` as step 0 (needs a CSV in the folder, or an already-stored dataset), then calls the other commands per invoice (`thefactory descargar`, `fev verificar`, `conciliar`, `derechos validar`, `rips generar`, `cuv generar`, `soporte generar`, `radicacion run`). State is read back from `tessia.proceso_estado`.

- PROC-01 — `proceso run [flags] <load folder>` (the folder is made absolute). `siesa` is never run. Phase names for the flags: convenio, thefactory, fev, conciliar, derechos, rips, cuv, soporte, radicacion. [src: cmd/tessia/cmd_proceso.go:29-140,149-265] [ext: none]
- PROC-02 — Flags and validation: `--invoices`, `--limit` (at least 0), `--no-replace`, `--csv`, `--nota-tecnica`, `--monto-maximo`, `--out`, `--cod-prestador`, `--from`, `--to`, `--skip a,b`, `--continue-on-error`, `--batch-radicacion` (default 200, at least 1), `--radicacion-interval` (default 1m, 0 disables), `--workers-<phase>` for thefactory, fev, conciliar, derechos, rips, cuv, soporte (each at least 1), `--json`, `--panel`. `--json` and `--panel` are mutually exclusive. ## Dependency map

- `convenio descargar` writes `Convenio_<dates>.csv` and `.csv.origin`, which `convenio preparar` (and `proceso run` step 0) reads. `serve` upload writes `Manual_*.csv`, which `proceso run` auto-detects.
- `convenio preparar` / `importar` write the dataset (`cargue*` tables) and `proceso_estado` (phase convenio). Everything else reads the dataset through `App.datasets()`: derechos, fev, rips, soporte, thefactory, conciliar, proceso, serve.
- `proceso run` calls `preparar` and then the per-invoice commands and `radicacion run`, reading each result back from `proceso_estado`. `conciliar` is reached only from `fev verificar` (VALOR_DIFERENTE) and, standalone, auto-runs `rips generar` and `cuv generar`.
- `seguimiento rebuild`, `fev` and `thefactory` fill `factura_valor_xml`, which the `serve` tracking table reads. `migrate retire-log` backfills the same state tables from the legacy `log`.
- `serve` starts `convenio descargar`, `proceso run` and `conciliar` as one-at-a-time live jobs, and reads the stores the commands write.

## Key Learnings

1. Phase commands never share in-memory state; `proceso run` invokes each standalone command with `--invoices <one>` and reads the outcome back from `tessia.proceso_estado`.
2. Standalone `conciliar` automatically runs `rips generar` and `cuv generar` for the rebuilt invoices, while `proceso run` disables that follow-up and routes the successors itself.
3. The `serve` job runner forces `Mode=Live` and `Yes=true` for every job, so no confirmation exists on the HTTP path, and the API has no authentication beyond the same-origin guard.
4. Prepared convenio data now lives only in MySQL (`cargue*` tables) behind `App.datasets()`; without `mysql.tessia_dsn` those commands fail with a dedicated Spanish error.
5. Config loading rejects unknown keys in the env file except six retired `TESSIA_*` names, and values that are empty never override a lower-precedence source.
